Part 1

Five ideas the whole codebase rests on

Read these first. Every design choice later in the tour follows from one of them.

The FEC's own files are the truth

Every campaign must report its money to the Federal Election Commission, which publishes the reports as large text files. The app counts from those files and nothing else. Other trackers, like OpenSecrets, are used only to double-check.

Money is whole cents, never floats

A float can turn $0.10 + $0.20 into $0.30000000000000004. The Money class stores an exact integer number of cents, so sums over millions of rows stay exact to the penny.

Time comes in two-year cycles

Federal elections run on two-year cycles named for the election year (the 2026 cycle covers 2025–26). Money is counted per cycle, and a "career" figure is the sum of a person's cycles from 1980 to 2026.

Some money must never be mixed

Money given to a campaign, money spent by outsiders about a race, and money a candidate lends themselves are different things. They live in separate columns and are never added together. Part 4 draws this.

The same input must give the same bytes

The FEC data is frozen in a dated snapshot. Rebuilding from that snapshot must reproduce the committed dataset exactly, down to the byte. If it doesn't, something in the code, the data or the method changed, and you stop and find out which.

Part 2

The assembly line

One command, python3 receipts/rebuild.py, runs the whole line in about two and a half minutes. Data moves left to right through five stations. Each color is one layer of data, and the same colors appear throughout this page.

Why a database in the middle?

The raw files hold tens of millions of rows. Loading them once into DuckDB means every money step can ask a precise SQL question ("AIPAC's checks to this candidate, by cycle") instead of re-reading gigabytes of text.

See the exact step order rebuild.py runs

Part 3 · worked example

Follow one receipt from filing to website

Abstract pipelines are hard to hold in your head, so here is a concrete one. In the 2026 cycle, AIPAC's PAC sent Rep. Darren Soto's campaign three checks of $5,000 — that is what the FEC bulk file shows. The dataset's figure is larger, $310,236.17: the bulk file drops nearly all of AIPAC's earmarked checks, so the pipeline substitutes the corrected figure from the FEC API. Here is each step those dollars take, with the real rows and the real code.

  1. Raw · data/raw/pas2/2026/itpas2.txt

    A line in a government text file

    The FEC's pas2 file lists every contribution from a committee to a candidate, one per line, fields split by |. This is one of the three checks, exactly as filed:

    C00797670|A|M10|P2026|202603309856885719|24K|CCM|DARREN SOTO FOR CONGRESS|KISSIMMEE|FL|34742|||09172025|5000|C00581074|H6FL09179|B232F183ECDC847AC8CA|1956674|||4033120261434825202

    Highlighted, left to right: the giver (C00797670, AIPAC PAC), the type (24K, a contribution to a candidate), the recipient, the date (Sept 17, 2025), the amount in dollars, and the candidate's FEC ID.

  2. Read · receipts/fec/

    A reader turns the line into a named record

    Each FEC file has one reader. It names all 22 fields, and it stops the build if a line has the wrong number of fields. A changed file layout is never skipped or guessed around.

    # receipts/fec/bulk_file.py
fields = line.rstrip('\n').split('|')
if len(fields) != width:
    raise LayoutChanged(f'... the FEC file layout changed')
yield self.record._make(fields)

# receipts/domain/money.py: '5000' becomes exact cents
Money.parse('5000')   # -> Money(cents=500000)
  3. Silver · committee_contributions table

    The store keeps every row, and says why it set any aside

    build_store.py loads every contribution into DuckDB. Rows that must not count stay in the table with a reason instead of being deleted, so the decision can be audited. Soto's 2026 AIPAC rows:

    committeecandidatedateamount_centsexcluded_because
    C00797670H6FL0917909172025500000—
    C00797670H6FL0917910302025500000—
    C00797670H6FL0917908052026500000—
    C00797670H6FL0917911052025-600voided_earmark

    The −$6 row is a refunded "earmark": a donor's money that AIPAC only passed along, then returned. The original pass-through isn't in the file, so subtracting the refund would invent a negative that never happened. A small rule in domain/ says exactly that:

    # receipts/domain/committee_money.py
def is_voided_earmark(contribution):
    return contribution.is_earmark and contribution.amount.is_negative
  4. Gold · gold.accepted_money_per_cycle

    A money step sums it per person, per cycle

    store/accepted_money.py adds up the rows that count — then substitutes the corrected AIPAC figure from the API merge (methodology §8 item 23), because the bulk file drops nearly all earmarked checks — and writes one row per person per cycle, still in cents. Soto, 2026:

    person_keycycleindividualcorporate_pacaipac_pac_direct
    S00120020261567917376290000031023617

    The three bulk-file checks sum to 1,500,000 cents = $15,000; the corrected figure is 31,023,617 cents = $310,236.17. dbt tests then check that every career total equals the sum of its cycles.

  5. Dataset · congress-money-tracker.json

    The dataset turns cents into dollars and applies the rules

    transform/compute_2026.py builds the 2026 columns and decides each member's 2026 verdict. "Dirty" is the project's term for money from sources other than individual donors:

    "individual_2026":   1567917.37,
"corp_2026":          629000.0,
"aipac_direct_2026":   310236.17,
"udp_benefit_2026":        0.0,
"dirty_2026":         939236.17,   // corp + AIPAC + UDP benefit
"clean_2026":            false,   // clean means dirty_2026 <= 0
"tier_balanced_2026":  "dirty"
    # receipts/domain/clean_2026.py
def verdict(in_120th, linked, unopposed, dirty, flagged):
    if in_120th and not linked:
        return None, UNLINKED      # no 2026 data: unknown, never "clean"
    if unopposed and dirty <= 0 and not flagged:
        return None, UNOPPOSED     # no contest: unknown, not clean
    return dirty <= 0 and not flagged, None
  6. Website · docs/ (three pages)

    The pages embed the dataset and draw it

    site/build_site.py fills the shared shell and the three page templates — the Story, Explore and Methodology — so the site needs no server. Explore embeds all 664 rows; the Story embeds precomputed aggregates computed from the same dataset. verify_site.py then decodes the embedded copies and checks that they match the dataset field by field. A reader who opens Soto's row in Explore sees the same $310,236.17, and can follow it back through every step above.

Common trap: "just fix the number"

If a figure looks wrong on the site, never edit the JSON or the page. Both are generated. Find which step produced it, fix the code or the rule there, and rebuild.

Part 4

Which money adds up, and which never does

The hardest rule for newcomers is that the columns overlap on purpose but are never blended. Two headline figures share parts:

Total accepted = individuals + corporate PACs + AIPAC PAC direct. This is money given to the campaign.

Dirty = corporate PACs + AIPAC PAC direct + UDP spending for them + UDP spending against their opponents. Individual donations are never dirty.

Shown separately, never added in: self-funding, other committees (party, leadership, labor PACs and so on), and all outside spending. Earmarks are a part of their parent column, never added a second time.

Common trap: adding outside spending to the total

A super PAC like UDP spends money about a race, on ads, without giving it to the campaign. Adding it to total_accepted would overstate what the candidate received. It counts toward "dirty" because it benefits the candidate, but it is never "accepted".

Part 5

The safety nets

The project's motto is show the evidence, never just the number. That only works if a wrong number can't slip through quietly. Seven checks stand along the line, and each one stops the build when it fails.

Baseline pins (4) are the heart of it. Every figure that new FEC data could move is stored once, in data/source/baseline.json. Code compares against it like this:

# receipts/store/all_ie.py
def pin_dollars(key, observed):
    recorded = expected(key, observed)
    if abs(observed - recorded) >= 0.005:
        raise SystemExit(f'all-IE {key} is {observed:,.2f}; the baseline says {recorded:,.2f}')

New FEC data is accepted only through a rebaseline. A weekly workflow freezes the latest files, records every figure, and opens a pull request showing each figure that moved, old next to new. A person reviews and merges it. Nothing new reaches the dataset without that review.

Common trap: making the check pass

When a check fails, the number is telling you something. Never adjust a figure, a pin or a test to match. Find out whether the code, the data or the method is wrong, and report it.

The audits have a blind spot

They check the dataset against its own definitions, so they can't notice a kind of money nobody thought to pull. That's how candidate self-funding went uncounted until November 2026. A new kind of money needs a coverage check, not only a math check.

Part 7

How code gets a setting

Every shared value (committee IDs, cycles, file paths, thresholds) lives in config.yaml. Code never types one in. It asks settings() at the moment it needs the value:

# receipts/transform/build_dataset.py
from receipts.common.settings import settings

def write_dataset(records):
    paths = settings().paths           # typed, read on first use
    with open(paths.dataset_json, 'w') as f:
        json.dump(records, f, indent=1)

settings() parses the file once into frozen, typed objects. A misspelled or missing key stops the run and names the key:

config.yaml cycles.current: expected int, got '2026'

A test imports every module in a fresh process and fails if any of them reads the config at import time, so importing code never has side effects.

Part 8

Your first hour

Run these in order from the repo root. The first rebuild needs the frozen FEC snapshot, about 1.7 GB on disk.

1. Install the package and its exact pinned versions
pip install -r requirements.txt
2. Run the fast checks: lint, types, unit tests with the coverage floor
ruff check receipts tests && mypy && python3 -m pytest -q --cov=receipts tests
3. Stage the frozen FEC data named in baseline.json
./fetch_snapshot.sh
4. Rebuild everything and run the audits (about 2½ minutes)
python3 receipts/rebuild.py
5. Prove it reproduced: this must print nothing
git diff --stat -- congress-money-tracker.csv congress-money-tracker.json
A good first exercise

Pick any member on the live site. Find their row in the JSON, then their rows in gold.accepted_money_per_cycle, then in committee_contributions. You've traced a receipt the way Part 3 did.

Part 9

House rules

The full contract is AGENTS.md. These are the ones people trip on in their first week.

  • Never hand-edit generated filesThe dataset, data/intermediate/ and the generated pages under docs/ (index.html, explore/index.html, methodology/index.html) are rebuilt from code. Change the code instead.
  • Never invent a figureIf a value isn't in a source you can cite, say you don't have it. If a route is blocked, write down the blocker.
  • One change per commitEach commit does one thing and names it (fix(dedup): …), so the history stays auditable.
  • New rule, same change, in the docsA new column or definition lands in methodology.md in the same change as the data.
  • Nothing goes public without CraigThe live site is the only public surface. Public figures change only through a reviewed pull request.
  • Pull first, then work on a branchOthers may have pushed since you looked. Never work the same files as another person or agent at the same time.
Part 10

Check yourself

Answer each in your head before opening it. Recalling an answer fixes it in memory far better than rereading.

Why does the app store $310,236.17 as 31,023,617?
Answer

Money is whole cents (principle 2). Integer cents add up exactly; floating-point dollars pick up rounding errors over millions of rows.

A member got $200,000 in UDP ads supporting them. Does their total_accepted go up?
Answer

No. UDP spent the money on ads about the race and never gave it to the campaign. It shows up in the UDP columns and counts toward dirty, never toward total_accepted.

Why was the −$6 row in Part 3 left out instead of subtracted?
Answer

It refunds an earmark whose original pass-through isn't in the file. Subtracting it would create a negative contribution that never happened, so the store marks it voided_earmark and keeps it for the record.

You fix a typo in a code comment and the rebuild's dataset md5 changes. What do you do?
Answer

Stop. A comment can't change the output, so something else differs: your inputs, a library version, or a real code change. Find which before committing anything. Never "fix" the dataset to match.

A member in the 120th Congress has no 2026 filings linked. Is clean_2026 true?
Answer

No, it's null (unknown). Missing data is never read as clean. The same goes for someone who ran unopposed: $0 dirty money means there was no contest, not a verified-clean campaign.

Where would you add a new FEC committee ID the code needs?
Answer

In config.yaml, and in the matching class in receipts/common/settings.py. Code reads it with settings(), never as a typed-in literal.

Reference

Glossary

FEC
Federal Election Commission. Publishes every federal campaign's money reports as bulk files.
cycle
A two-year election period named for its election year. The 2026 cycle covers 2025–26.
weball
FEC file of each candidate's summary totals per cycle: receipts, loans, cash on hand.
pas2
FEC file of itemized contributions from committees (PACs) to candidates.
cm
The committee master file: every registered committee and the candidate it belongs to.
PAC
Political action committee. A group that raises money and gives it to candidates.
IE
Independent expenditure: money spent for or against a candidate without giving it to them, such as ads.
UDP
United Democracy Project, a super PAC affiliated with AIPAC. Its spending is tracked separately.
earmark
A donor's money that a committee only passes along to a campaign. It's a subset of its column and never counted twice.
dirty money
The project's term for corporate PAC + AIPAC PAC direct + UDP benefit. Individual donations never count.
tier
A softer reading of dirty under a tolerance preset (Strict, Balanced, Lenient): clean, below threshold, or dirty.
silver / gold
Silver tables hold cleaned raw rows; gold tables hold each money step's per-person totals.
snapshot
A frozen, dated copy of the FEC files, published as a GitHub Release, so a rebuild always reads the same input.
baseline
data/source/baseline.json: every figure new data could move, recorded from one snapshot.
rebaseline
Accepting a new snapshot: record every figure again and review what moved in a pull request.
freshness
A separate report of money filed after the bulk snapshot's cutoff. Shown on its own, never merged into totals.
